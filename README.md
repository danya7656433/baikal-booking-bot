# Дача на Байкале

Telegram-бот, браузерное бронирование и лендинг гостевого дома в Максимихе.

## Локальный просмотр

Требуются Python 3.12+, Node.js 20.19+ и npm.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
cd frontend
npm install
npm run build
cd ..
.\.venv\Scripts\python.exe -m webapp.run --demo --port 8000
```

Открыть http://127.0.0.1:8000. Главная страница — лендинг;
`/#book` — бронирование, `/#bookings` — личный кабинет.
В бронировании есть переключатель демонстрационных ролей гостя и администратора.
Демо использует отдельную базу `.demo/booking.db`, не запускает бота
и не отправляет уведомления в Telegram. Не публикуйте демонстрационный сервер.

## Лендинг

- Полноэкранная фотографическая сцена Three.js: объёмная поверхность воды,
  преломление, параллакс и рябь по нажатию.
- Пауза анимации, поддержка `prefers-reduced-motion`, остановка за пределами
  экрана, освобождение WebGL при переходе к бронированию.
- При отсутствии WebGL остаётся фотография, все ссылки работают.
- Фотографии номеров и территории, галереи, условия поездки, контакты.
- Раздельная загрузка 3D-модуля: он не нужен на страницах бронирования.

Авторство и лицензия фотографии бухты: [ATTRIBUTION.md](frontend/public/media/ATTRIBUTION.md).
Фотографии объекта взяты из существующей папки `photos/`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
cd frontend
npm run build
npm test
cd ..
.\.venv\Scripts\python.exe docs/check_landing_pixels.py
```

Для браузерных тестов должен работать демосервер на порту 8000 и быть установлен
Google Chrome. Скриншоты сохраняются в `test-results/`.

## Подключение Рабочего Сервера

Собрать `frontend`, настроить переменные из `.env.example`, запустить
`python -m webapp.run --host 127.0.0.1 --port 8000` за HTTPS reverse proxy.
Для API ограничить размер тела запроса на proxy до 9 МБ, включая chunked uploads.
Бот (`python main.py`) и webapp должны использовать одну постоянную базу SQLite
и каталог `DATA_DIR`; резервные копии нужны до применения миграций.

В BotFather настроить домен Telegram Login и HTTPS URL Mini App
с окончанием `/#book`. Для браузерного входа нужен `BOT_USERNAME`.
`ADMIN_USER_IDS` содержит числовые ID администраторов, не ID группы.
Оплата — перевод по `PAYMENT_INSTRUCTIONS`, загрузка фотографии чека
и ручное подтверждение поступления денег администратором.

Локальный просмотр не означает публикацию сайта или настройку рабочего бота.
До запуска нужны домен, HTTPS, реквизиты, политика обработки персональных данных
и проверка реального входа/уведомлений в Telegram.

Dockerfile собирает фронтенд отдельным этапом. Стандартная команда контейнера
остаётся `python main.py` для совместимости с существующим размещением бота.
Для отдельного web-сервиса команда запуска:
`python -m webapp.run --host 0.0.0.0 --port 8000`.
Ему нужны HTTPS-прокси и тот же постоянный каталог данных, что и боту.
Если хостинг не поддерживает общую файловую систему сервисов, потребуется
совместный запуск в одном контейнере или перенос базы; две независимые копии
SQLite не синхронизируют бронирования.
