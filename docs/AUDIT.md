# Проверка проекта

Дата: 7 сентября 2026. Рабочая ветка: `codex/webapp-audit`.

## Исправлено

- Общие компоненты номеров, сочетания и весь дом учитываются при проверке
  занятости. SQLite-триггеры защищают от пересечений и записей старого бота.
- Отмена проверяет принадлежность заявки. Подстановка гостевых данных
  в HTML-карточки экранируется.
- Новая база получает текущий год. Отсутствие переменных бота не мешает
  локальной проверке webapp; сам бот требует настройки при запуске.
- Копии базы не перезаписываются повторным запуском в одну секунду;
  аварийное завершение возвращает ненулевой код.
- Новые заявки webapp сохраняют цену и ключ повторного запроса.
  Повторное подтверждение одного чека не начисляет платёж заново.
- Сессии webapp хранят хеш токена, имеют срок жизни и проверяют подпись
  Telegram. Чеки доступны только владельцу заявки и администраторам.
- Обновлены зависимости с известными уязвимостями. Текущий `pip-audit`
  не обнаружил известных уязвимостей в установленном окружении.
- Тесты уведомлений явно задают ID администратора и больше не зависят
  от порядка импорта конфигурации или локальной `.env`.

## Проверка интерфейса

Лендинг использует реальные фотографии, Three.js и отдельные страницы
бронирования. Браузерные тесты проверяют загрузку фотографий, отсутствие
горизонтального переполнения, размещение главного заголовка и CTA,
движение и паузу сцены, повторное открытие, галерею, FAQ и fallback без WebGL.
Скриншоты и проверка цвета пикселей находятся в `test-results/`.

## Результаты статического сканирования

`security-scan.json` содержит три сигнала Bandit, проверенных вручную:

- `db/inventory_guards.py`: SQL для триггеров собирается только из констант
  кода. Пользовательский ввод не интерполируется в SQL.
- `webapp/run.py`: пустой `BOT_TOKEN` отключает Telegram в локальном демо.
- `bot/routers/admin_tools.py`: `os.execl` перезапускает текущий Python
  после подтверждения администратора, без shell.

Отчёт сканера сохранён без подавления этих предупреждений.

## Оставшиеся ограничения

- Старый крупный роутер и его глобальные сессии требуют дальнейшего
  разделения; всю логику старого бота проверенные сценарии не покрывают.
- Редактирование дат существующей брони и ручное создание заявки
  администратором ещё не добавлены в новый webapp.
- Возврат учитывается отдельной операцией, но не имеет ключа идемпотентности.
  Повторную отправку после сетевого сбоя нужно сверять с историей платежей.
- До публичного запуска требуется ограничение потоковых загрузок на proxy,
  HTTPS, домен Telegram Login, реквизиты и юридические документы.
- Реальный Telegram Login, уведомления и размещение на сервере не проверены:
  локальный демосервер использует отдельную базу и не отправляет сообщения.
- Python сообщает о deprecated `datetime.utcnow` и тестовом адаптере httpx;
  это технический долг, не падение текущих проверок.
- Three.js загружается отдельно; его модуль около 512 КБ до gzip.
  Производительность на старых физических устройствах ещё не измерена.

Проверки не означают отсутствия всех возможных ошибок или готовности
инфраструктуры к публичному запуску.
